# Admin KTA Reset (Hard Reset) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a superadmin/admin_nasional hard-reset a member's KTA so the member can submit a fresh application from the mobile app.

**Architecture:** One guarded API endpoint runs a single transaction that revokes the member's `kartu_anggota` document + QR, decrements affected batch counters, and deletes all of the member's `kta_application` rows (histories cascade). An audit snapshot preserves what was removed. `/kta-applications/me` then returns `null`, so the existing mobile banner shows "Ajukan KTA" with no mobile change. A confirmation-guarded button on the web member detail page calls it.

**Tech Stack:** NestJS + Prisma (PostgreSQL) API, Next.js (app router) web, Jest (API), Vitest/tsc/eslint (web).

**Spec:** inline design approved 2026-11-15 (see Design Summary below).

## Design Summary

- Endpoint: `POST /kta-applications/members/:memberId/reset`, `@Roles('superadmin', 'admin_nasional')`.
- Keeps the member record and `nomorAnggota`; deletes only `kta_application` rows and revokes card documents.
- Decrements `ktaBatch.totalGenerated` for deleted `CARD_GENERATED` apps that belong to a batch.
- Writes exactly one `AuditLog` (`KTA_RESET`) with a JSON snapshot of deleted apps + revoked docs.
- Idempotent: a member with no applications/cards returns `{ deletedApplications: 0, revokedDocuments: 0 }`.

## Global Constraints

- Roles allowed: `superadmin`, `admin_nasional` only.
- Delete applications inside a transaction; histories cascade via the existing FK (`onDelete: Cascade`).
- Never delete the `anggota` row; never clear `anggota.nomorAnggota`.
- Revoke, do not delete, card documents: `dokumen.status = 'revoked'`, `qr_validation.is_valid = false`.
- No mobile code changes; `/kta-applications/me` returning `null` is the contract the banner relies on.

## Review Focus

1. Member with zero applications and zero card docs → returns 0s, no crash, no negative batch counters.
2. Member with mixed apps (e.g., `CARD_GENERATED` + `CANCELLED`) → all deleted; only `CARD_GENERATED` batch counts decremented.
3. Member with multiple card docs/QRs → every `kartu_anggota` doc revoked and every active QR invalidated.
4. Caller without `superadmin`/`admin_nasional` → 403; nonexistent `memberId` → 404; no partial writes.
5. After reset, `GET /kta-applications/me` returns `null` and `POST /kta-applications/me` succeeds for the member.

```ts
async resetMemberKta(
  memberId: string,
  actor: { id: string; role: string },
): Promise<{ success: true; deletedApplications: number; revokedDocuments: number }> {
  const member = await this.prisma.anggota.findFirst({
    where: { id: memberId, deletedAt: null },
    select: { id: true, rantingId: true, nomorAnggota: true },
  });
  if (!member) throw new NotFoundException('Anggota tidak ditemukan');

  const apps = await this.prisma.ktaApplication.findMany({
    where: { anggotaId: memberId },
    select: { id: true, status: true, nomorAnggota: true, batchId: true },
  });
  const docs = await this.prisma.dokumen.findMany({
    where: { anggotaId: memberId, tipe: 'kartu_anggota' },
    select: { id: true, status: true },
  });

  const docIds = docs.map((d) => d.id);
  const perBatch = new Map<string, number>();
  for (const app of apps) {
    if (app.status === 'CARD_GENERATED' && app.batchId) {
      perBatch.set(app.batchId, (perBatch.get(app.batchId) ?? 0) + 1);
    }
  }

  await this.prisma.$transaction(async (tx) => {
    if (docIds.length > 0) {
      await tx.dokumen.updateMany({ where: { id: { in: docIds } }, data: { status: 'revoked' } });
      await tx.qRValidation.updateMany({
        where: { dokumenId: { in: docIds }, isValid: true },
        data: { isValid: false },
      });
    }
    for (const [batchId, count] of perBatch) {
      await tx.ktaBatch.update({
        where: { id: batchId },
        data: { totalGenerated: { decrement: count } },
      });
    }
    await tx.ktaApplication.deleteMany({ where: { anggotaId: memberId } });
  });

  this.audit('KTA_RESET', memberId, actor.id, {
    anggotaId: memberId,
    rantingId: member.rantingId,
    nomorAnggota: member.nomorAnggota,
    role: actor.role,
    deletedApplications: apps.map((a) => ({ id: a.id, status: a.status, nomorAnggota: a.nomorAnggota })),
    revokedDocuments: docs.map((d) => ({ id: d.id, status: d.status })),
  });

  return { success: true, deletedApplications: apps.length, revokedDocuments: docs.length };
}
```

const handleResetKta = async () => {
  if (!member) return;
  setActionLoading('reset-kta');
  try {
    const { data } = await apiClient.post(`/kta-applications/members/${member.id}/reset`);
    const res = data?.data ?? data;
    toast(
      'success',
      res?.deletedApplications
        ? `KTA direset: ${res.deletedApplications} pengajuan dihapus, ${res.revokedDocuments} kartu dicabut`
        : 'Tidak ada data KTA untuk direset',
    );
    setShowResetKtaModal(false);
    await fetchMember();
  } catch (err) {
    const apiError = (err as { response?: { data?: { message?: string } } })?.response?.data?.message;
    toast('error', apiError || 'Gagal mereset KTA');
  } finally {
    setActionLoading(null);
  }
};
